前言

今天系统的学习了 Java 线程池（Thread Pool）相关的知识。线程池是并发编程中最核心的组件之一，它通过复用线程来避免频繁创建/销毁线程带来的性能开销。这篇文章从「创建方式」、「execute 与 submit 的区别」、以及「核心参数与执行流程」三个方面，配图+代码做一个完整梳理。

为什么要用线程池？一句话总结：控制资源、复用线程、统一管理。

一、线程池的创建方式

Java 中创建线程池主要有两大类方式：通过 Executors 工具类的工厂方法（快捷），以及直接 new ThreadPoolExecutor（自定义）。

重要提示：《阿里巴巴 Java 开发手册》明确建议不要用 Executors 创建线程池，原因在于：

创建方式 隐患
newFixedThreadPool / newSingleThreadExecutor 使用无界队列 LinkedBlockingQueue，任务堆积可能耗尽内存 OOM
newCachedThreadPool 最大线程数为 Integer.MAX_VALUE，线程数无上限，可能创建过多线程导致 OOM
newScheduledThreadPool 支持定时，但同样可能堆积大量延时任务

正确姿势：手动 new ThreadPoolExecutor(...)，参数显式、清晰可控。

三、ThreadPoolExecutor 核心参数详解

ThreadPoolExecutor 最完整的构造方法包含 7 个参数：

3.1 各参数含义

参数 含义
corePoolSize 核心线程数：线程池常驻线程，即使空闲也不会被回收（除非 allowCoreThreadTimeOut(true)）
maximumPoolSize 最大线程数：线程池能容纳的最大线程数量
keepAliveTime 空闲存活时间：当线程数超过核心线程数、且线程处于空闲时，超过此时间会被回收（只针对超出核心数的线程）
unit keepAliveTime 的时间单位，如 TimeUnit.SECONDS
workQueue 任务队列：当核心线程都忙时，任务先进入这里排队
threadFactory 线程工厂：用来创建线程，可自定义线程名、优先级等，方便排查
handler 拒绝策略：当任务无法被处理时的兜底方案

3.2 任务处理流程（重点）

当一个任务被提交时，线程池按固定顺序判断：

  1. 当前线程数 < 核心线程数 → 直接创建核心线程执行；
  2. 当前线程数 ≥ 核心线程数 → 任务放入任务队列等待；
  3. 任务队列已满 且线程数 < 最大线程数 → 创建非核心线程执行；
  4. 任务队列已满、且线程数 ≥ 最大线程数 → 触发拒绝策略。
flowchart TD
    A[提交任务] --> B{当前线程数 < 核心线程数?}
    B -->|是| C[创建核心线程执行任务]
    B -->|否| D{任务队列是否已满?}
    D -->|否| E[任务放入队列等待]
    D -->|是| F{当前线程数 < 最大线程数?}
    F -->|是| G[创建非核心线程执行任务]
    F -->|否| H[触发拒绝策略 handler]

五、参数配置建议

场景 建议
CPU 密集型 核心线程数 ≈ CPU 核心数（Runtime.getRuntime().availableProcessors()）
IO 密集型 核心线程数 ≈ CPU 核心数 × 2，或更大（因为线程大部分时间在等待 IO）
队列选择 有界队列（ArrayBlockingQueue）更安全，避免无界队列 OOM
拒绝策略 默认 AbortPolicy 如果不能容忍丢任务，用 CallerRunsPolicy 做慢速限流
线程命名 一定自定义 threadFactory 起个好认的名字，方便排查问题

总结

  1. 创建方式：优先手动 new ThreadPoolExecutor，避免 Executors 的无界队列/无限线程隐患
  2. execute vs submit：execute 无返回、异常不可见；submit 返回 Future、能拿到结果和异常
  3. 七大参数：核心数、最大数、存活时间、单位、队列、线程工厂、拒绝策略
  4. 执行顺序：核心线程 ⏵ 任务队列 ⏵ 非核心线程（扩到最大）⏵ 拒绝策略

线程池是 Java 并发的基础，掌握它的执行流程和参数，是每一个后端工程师的必修课。希望这篇笔记能帮你一次理清。
