Spring AI 2.0 实战：从零构建一个有记忆的问答 Agent

引言

大模型应用开发中，「多轮对话记忆」是一个绕不开的课题。用户不希望每次发问都重复一遍自己的背景、偏好或前文信息。Spring AI 作为 Java 生态里最主流的生成式 AI 框架，在 2.0 版本中对 Agent 能力和记忆机制做了大量重构，让我们可以几乎零侵入地给应用加上「记忆」。

本文基于 Spring AI 2.0.0 GA（2026-06-12 发布），从零搭建一个有记忆、可联网的问答式 Agent，并解释它背后的原理。代码可以直接复制运行。

Spring AI 2.0 带来了什么

Spring AI 2.0.0 是一次以「工程质量」为导向的重量级发布，主要变化包括：

  • 基线升级：基于 Spring Boot 4.0/4.1 与 Spring Framework 7，最低 Java 17
  • Jackson 3：JSON 序列化能力显著增强，新增 JsonHelper 工具
  • JSpecify 空安全：全代码库引入空安全注解，API 语义更清晰
  • 组合式工具调用（Composable Tool Calling）：大幅重构了 Agent 执行工具的内部机制，让工具编排、渐进式发现更加灵活
  • 注解化 MCP：@McpTool / @McpResource / @McpPrompt 让 Spring Bean 直接暴露为 MCP 服务
  • 记忆改进：修复了 ChatMemory 仓库相关问题，并持续优化与 RAG 的组合体验

对于本次 Demo，我们主要用到的是 ChatMemory 记忆 + Advisor 装饰器 + 工具调用 这套组合。

核心概念：Agent 的「记忆」

「记忆」可以拆成两类：

类型 作用 存储方式
短期记忆 单次会话内的上下文连贯 对话消息序列
长期记忆 跨会话的用户偏好、事实 数据库 / Redis 向量库

本文聚焦短期记忆：在同一会话中，让 Agent 记得用户之前说过的话。

Agent 记忆工作流程

flowchart TD
    A[用户输入] --> B{会话ID是否已存在}
    B -->|是| C[从 ChatMemory 读取历史消息]
    B -->|否| D[创建新会话]
    D --> C
    C --> E[组装 Prompt: 系统提示 + 历史 + 当前问题]
    E --> F[调用 ChatModel]
    F --> G[LLM 返回回答]
    G --> H[把本轮问答写入 ChatMemory]
    H --> I[返回给用户]

Spring AI 记忆核心组件

Spring AI 通过下面几个关键抽象把记忆封装得很干净：

  • ChatMemory：记忆核心接口，定义 add / get / clear 方法
  • ChatMemoryRepository：记忆的实际存储层，内置内存、JDBC、Redis 等实现，也支持自定义（比如存到 MySQL / PostgreSQL）
  • MessageChatMemoryAdvisor：记忆装饰器，在每次请求时自动注入历史消息、并在响应后自动写入记忆

下面这张图展示了它们的关系：

sequenceDiagram
    participant U as 用户
    participant C as ChatClient
    participant A as MessageChatMemoryAdvisor
    participant M as ChatMemory
    participant R as ChatMemoryRepository

    U->>C: user("你好，我叫小明")
    C->>A: 调用前置逻辑
    A->>M: get(conversationId)
    M->>R: 读取历史消息
    R-->>M: 返回消息列表
    M-->>A: 历史消息
    A-->>C: 消息 + 系统提示组装 Prompt
    C->>LLM: 请求大模型
    LLM-->>C: 回答
    C->>A: 调用后置逻辑
    A->>M: add(assistantMessage)
    M->>R: 写入记忆
    C-->>U: 回复用户

原理解读：为什么这样就有记忆了

MessageChatMemoryAdvisor 是一个典型的 Advisor 装饰器，它在 Call 前后做了两件事：

  1. 调用前：根据 CONVERSATION_ID 从 ChatMemory 拉取历史消息，与系统提示、当前输入组装成完整 Prompt 发送给模型。
  2. 调用后：把本轮的用户消息和模型回答追加进 ChatMemory，供下一轮使用。

这样 LLM 每次请求都带着完整的上下文，表现出「记住」的效果；而不同 conversationId 天然隔离了不同用户/会话的记忆。

总结

通过 Spring AI 2.0，我们只用了短短几个类，就完成了一个具备多轮记忆和工具调用能力的问答 Agent，并且做到了：

  • ✅ 记忆零侵入：ChatMemory + MessageChatMemoryAdvisor 自动管理上下文
  • ✅ 会话隔离：用 conversationId 区分不同用户
  • ✅ 可持久化：切换 ChatMemoryRepository 即可换存储介质
  • ✅ 可扩展：@Tool 让 Agent 具备「动手」能力，2.0 的组合式工具调用更进一步支持多工具编排

Spring AI 2.0 把 Java 团队的 Agent 开发门槛降到了「写普通 Spring 服务」的水平。如果你也想给自己的应用加上 AI 能力，不妨从本文的 Demo 开始。
